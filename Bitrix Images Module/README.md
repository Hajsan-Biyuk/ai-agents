# Sheer WebP — модуль 1С-Битрикс (каталог Aspro MAX)

Создаёт WebP-копии рядом с оригиналом (`photo.jpg` → `photo.jpg.webp`) и отдаёт их браузеру. Оригиналы не изменяются, откат полный.

Версия **1.7.1**. Заточен под витрину вроде atriumceramic.ru: Bitrix + Aspro MAX, много `resize_cache`, городские поддомены.

На боевой сайт **не ставить**, пока явно не попросите.

## Установка (когда разрешите)

1. Скопируйте `sheer.webp` в `/local/modules/sheer.webp/`.
2. Marketplace → Установленные решения → **Sheer WebP**.
3. Проверьте: агенты на cron, GD/`imagewebp` или Imagick WEBP.
4. Сначала 20–30 карточек товара, не весь каталог за раз.

## Как работает на этом каталоге

- Массовое сканирование: `/upload/iblock`, `/upload/CMax`, `/upload/medialibrary`. Не весь `/upload`, не шаблоны, не `resize_cache`.
- Превью Aspro (600 / 900 / 1400 / 1500) ставятся в очередь при просмотре или ресайзе. Кодирует cron, не хит посетителя.
- Миниатюры 50×50, 52, 60, 80 (порог 120 px) не конвертируются.
- SVG, GIF, иконки — нет.
- Качество 90, оригинал не пережимается. Если у PNG WebP с потерями тяжелее оригинала, модуль пробует WebP без потерь (плоские превью на белом фоне так обычно в разы легче).
- Поддомены города — те же файлы, второй раз гонять не нужно.
- HTML-подмена URL работает, если браузер шлёт `image/webp` (или это Chrome/Firefox/Edge, iOS 14+). Настольный Safari без `image/webp` в Accept получает JPEG. Чужой CDN не трогается.
- При включённом **композитном кеше** HTML не переписывается (кеш отдал бы WebP всем браузерам) — WebP тогда отдаёт только nginx-сниппет или `.htaccess`. Картинки страницы при этом ставятся в очередь, когда Битрикс собирает её для кеша: так конвертируются только реально показываемые превью `resize_cache`, а не все когда-либо нарезанные размеры.
- Кнопка «Очистить очередь» останавливает сканирование и удаляет ожидающие записи; готовые WebP и оригиналы не трогаются.
- Кнопка «Прогреть по sitemap» обходит страницы из `sitemap.xml` (сначала разделы, потом карточки) агентом из cron, в несколько потоков (настройка «Потоков прогрева», по умолчанию 4 ≈ 100 страниц в минуту). Так в очередь встают картинки, которые реально показываются на сайте. Mac/браузер держать открытыми не нужно.
- **Ночной режим** (настройки): в заданные часы конвертация идёт со своей скоростью, прогрев по sitemap — только ночью. Днём — щадящая скорость «Картинок в минуту».
- Кнопка **«Пауза»** останавливает фоновую работу cron, не трогая композитный кеш; посетители её не снимают. Очередь при паузе продолжает копиться.
- Загрузки в админке тоже идут в очередь, кодирует только cron.

## Важно

1. **Cron.** Без агентов по cron очередь не разберётся: на хитах агент намеренно ничего не кодирует. Нужны `define("BX_CRONTAB_SUPPORT", true);` в `dbconn.php` и `cron_events.php` раз в минуту. Агент из cron кодирует до ~25 с за запуск и не больше 50 картинок (настройка «Картинок в минуту»).
2. **nginx.** `.htaccess` по умолчанию выключен. Либо сниппет из настроек, либо оставьте подмену URL.
3. **Диск.** Оригиналы остаются. Экономия в админке — трафик, не гигабайты на сервере.
4. Фото крупнее 2560 px по длинной стороне получают **уменьшенную** WebP-копию (настройка «Уменьшать WebP до»; оригинал не меняется). Не обрабатываются только файлы > 30 МБ или > 80 Мп — аварийный потолок по памяти.

## Откат

Вкладка «Откат» выключает модуль, чистит композитный кеш и удаляет только `*.jpg.webp`, созданные модулем (чужие `.webp` остаются), и очередь. Оригиналы на месте. Чтобы конвертировать заново — включить модуль в настройках.
