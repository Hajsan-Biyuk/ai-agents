# Чек-лист импорта товаров — @pars

Перед сдачей задачи пройти все применимые пункты.

## 1. Источник данных

- [ ] Файл/URL указан, кодировка UTF-8
- [ ] Первая строка Excel — заголовки (или явно указана строка данных)
- [ ] Пустые строки и дубликаты ключей обработаны
- [ ] Ключ upsert выбран и задокументирован (артикул / CODE / SKU / slug)

## 2. Маппинг

- [ ] Таблица «колонка источника → поле CMS» согласована или записана в отчёт
- [ ] Обязательные поля CMS не пустые (название, категория, цена — по ТЗ)
- [ ] Slug транслитом, без кириллицы в URL (если не оговорено иное)
- [ ] Цены: формат числа, валюта, округление

## 3. Dry-run

- [ ] Запущен dry-run **до** реального импорта
- [ ] Отчёт: `created`, `updated`, `skipped`, `errors`
- [ ] Критичные errors = 0 (или явно согласованы с пользователем)
- [ ] Примеры 3–5 строк diff показаны пользователю

## 4. Импорт

- [ ] Реальный импорт — **только по явному запросу** после dry-run
- [ ] Бэкап БД / экспорт напоминание пользователю (массовое обновление)
- [ ] Нет хардкода паролей в скриптах
- [ ] Временные `local/tools/*_import.php` — план удаления после импорта

## 5. Проверка на сайте

- [ ] Админка: новые/обновлённые записи на месте
- [ ] Фронт: 2–3 карточки — название, цена, категория, фото
- [ ] Фильтр/каталог: товар в нужной секции
- [ ] **Bitrix + Aspro Max:** если импортёр создаёт бренды — на `/info/brands/` ссылки кликабельны (не `wti` без href из‑за пустого `DETAIL_TEXT`)
- [ ] Кеш CMS сброшен (WP object cache / Bitrix «Очистить кеш»)

## 6. Парсинг поставщика (если было)

- [ ] URL и дата парсинга зафиксированы
- [ ] Не перезаписаны локальные поля без ТЗ (например SEO-текст)
- [ ] Изображения: лицензия/источник, локальная копия или hotlink по ТЗ

## 7. Документация

- [ ] Лог в `агенты/PARS/_ЛОГИ/YYYY-MM-DD_{project}_{task}.md`
- [ ] Новый устойчивый паттерн → `паттерн/` или `примеры/`

## Вердикт

```
VERDICT: PASS | FAIL | BLOCKED
```

**BLOCKED** — нет файла, нет доступа к CMS, неясный маппинг без ответа пользователя.
