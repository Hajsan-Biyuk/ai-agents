# Линтер и форматтер — при любой работе с кодом

Написал или поправил код — до коммита / заливки прогони **линтер** и **форматтер** по изменённым файлам. Ошибки линтера исправить; не исправил — сказать, какие и почему.

## Чем

Сначала конфиг проекта (`package.json` scripts, `.eslintrc*`, `.prettierrc*`, `.stylelintrc*`, `phpcs.xml`, `pyproject.toml`) — им и только им. Нет конфига — по умолчанию:

| Код | Линтер | Форматтер |
|---|---|---|
| PHP | `php -l файл` | `npx -p prettier -p @prettier/plugin-php prettier --plugin=@prettier/plugin-php --write файл` (только новые файлы) |
| JS / TS | `npx eslint файл` | `npx prettier --write файл` |
| CSS / SCSS | `npx stylelint файл` | `npx prettier --write файл` |
| HTML / Astro | `npx astro check` (Astro) | `npx prettier --write файл` |
| Python | `uvx ruff check файл` | `uvx ruff format файл` |
| JSON / YAML | — | `npx prettier --write файл` |

## Осторожно

- **Форматировать только своё.** Чужой/легаси код (шаблоны Битрикс/Аспро, темы WP, плагины, файлы с боя через бридж) целиком не переформатировать — дифф на весь файл, правку не видно, ломается сравнение с прод-версией. Там: линтер на весь файл, форматтер — только для новых файлов или своих строк.
- Минифицированные (`*.min.*`), `vendor/`, `node_modules/`, `dist/`, `bitrix/modules/`, `wp-admin/`, `wp-includes/` — не трогать.
- PHP-файл перед заливкой на бой через бридж/SFTP — `php -l` обязательно: синтаксическая ошибка = белый экран сайта.
- Конфиги и dev-зависимости линтеров в проект не добавлять без запроса — запускать через `npx` / `uvx`.
